# 网站搬到自己的服务器（2026-10-29）

## 决定

- MortyYJT 要求网站直接部署在自己的服务器（腾讯云香港轻量服务器 `43.161.224.82`，与 LeapAshore 同机），域名 `mortyyjt.site`；不再用 GitHub Pages。
- 部署方式：推送到 main 后由 GitHub Actions 自动部署（用户选择）。
- `mortyyjt.github.io`：停用（用户选择）。部署流程里发布到 Pages 的那一步已删除；`MortyYJT.github.io` 仓库和其中最后一版静态文件暂时原样保留，之后再决定删除还是改成跳转。

## 怎么搭的

- 服务器 80/443 端口被 LeapAshore 的 Caddy（Docker）占着，网站只能共用它。站点配置在 LeapAshore 仓库 `deploy/Caddyfile` 末尾（`mortyyjt.site` + `www` 跳转），`compose.prod.yaml` 把 `/srv/mortyyjt.site` 只读挂进 Caddy 容器。见 LeapAshore PR #28。
- 网站文件放在服务器 `/srv/mortyyjt.site`（属主 ubuntu）。
- 部署钥匙：专用 ed25519，私钥只存在本仓库 Secret `SITE_DEPLOY_KEY`（本机副本已删）。服务器 `~/.ssh/authorized_keys` 里用 `command="/usr/bin/rrsync /srv/mortyyjt.site",restrict` 限制：只能 rsync 进这个目录，开不了 shell，也出不了目录（2026-10-29 实测）。改动前的备份：`~/.ssh/authorized_keys.bak-20261029-site`。
- `deploy.yml` 的 rsync：`--delay-updates` 让新文件最后一起换上；`--filter='P /_next/static/**'` 保护旧的带哈希资源不被删，解决了之前「部署后旧缓存页面没样式」的待办。旧资源会慢慢累积，每次几百 KB，量大了再手动清。
- 服务器主机公钥在 `deploy.yml` 里固定，不在首次连接时盲信。

## 验证（2026-10-29）

- 本地用同一段 Caddy 配置跑真实导出：`/`、`/projects`、`/profile`、`/friends`、`/pictures` 200，未知路径 404 并显示网站的 404 页，`/_next/static` 带一年 immutable 缓存。
- 用 Linux 标准 rsync 和临时钥匙（已删除）对服务器按 `deploy.yml` 的同一条命令连续部署两次：多余文件被删、旧资源保留。
